# 单步主控与持久化尝试账本

`StepRunner` 串起一次完整的控制流程：采集 → 校验 → 模型决策 → 再次采集 → 校验快照和候选 → 控制器提交。仍需提供可靠的 `ObservationSource`、`PolicyBackend` 和 `ActionExecutor`；现有 Power.log 投影保持 incomplete，不能进入执行。

## 离线演示

```powershell
cargo run --offline -- loop-demo
```

输出五条 JSON：稳定局面可记录、版本变化拒绝、同版本候选内容变化拒绝、运行取消拒绝、同状态重复提交拒绝。使用合成观测和记录执行器，不需要模型服务，不发送游戏输入。`recorded` 不等于真实执行成功。

## 主控约束

- 时间预算从首次采集前开始，覆盖采集、推理与再采集；阻塞适配器不能被抢占，但返回后超时结果不会继续提交。
- 只有完整、可行动阶段且候选 ID 唯一的观测进入策略。再次采集失败、阶段/会话/版本变化、候选内容变化都会拒绝。候选仅重排且语义相同允许通过。
- `stop_token()` 可跨线程停止整个 runner；后续新建时间窗口也不能恢复该运行。最后检查后的取消仍无法撤销已经进入的执行器。
- 执行器错误或 `Uncertain` 锁住后续步骤，不能靠新版本自动继续。独立结果确认和恢复流程尚未实现，因此当前没有清除此状态的快捷接口。
- 一个 runner 保留跨步骤尝试记录，必须持续复用；模型/采集失败不会伪造已执行成功。

`StepResult.result` 返回详细类型化错误；`StepResult.trace` 可逐条序列化成 JSONL，包含协议版本、步骤编号、两次语义观测、决策、分阶段时间和固定错误代码。它不导出适配器错误原文、原始游戏日志或模型局面。`confirmed_by_adapter` 仅表示执行器按接口契约返回 Confirmed，runner 不独立证明游戏效果。执行错误用 `failed_requires_review`，不把可能已发送输入的失败描述为普通拒绝。

## 持久账本

```rust
let mut runner = StepRunner::with_journal(".data/attempts.jsonl")?;
```

目录需已存在。默认 runner/controller 仍只用内存；`with_journal` 显式启用持久化。底层使用标准库文件独占锁，拒绝第二个写入者；进程退出释放锁，不生成需要手动清理的锁文件。

每次尝试先写 JSONL 意图并 `sync_all`，成功后才允许调用执行器；随后记录 Recorded/Confirmed/Uncertain/Failed 结果。同步消耗预算或期间取消时，记录 NotDispatched，仍保留去重键。写入/同步失败停止提交并要求恢复。错误字符串不写入账本。

重开账本恢复 `(session_id, decision_id)` 和 `(session_id, revision)`。有未完成意图、Uncertain 或 Failed 时锁住所有新步骤；完整且明确完成的记录允许继续，但旧状态仍不可重试。损坏、未结束行、乱序、重复意图、无前置意图的结果和结果身份不匹配均拒绝打开；绝不截掉尾部后假装可继续。

账本限制 16 MiB、单条 4096 字节，达到上限要求审查和归档，不自动丢弃历史。它不是防篡改存储；依赖文件系统/设备的同步保证及独占锁协作。

**真实适配器必须提供跨进程稳定的对局身份和版本定义**，才能使用持久去重。当前 watcher 的运行标识用于隔离只读快照，不能直接作为跨重启游戏身份。不能通过换 session ID、删除账本或新建 runner 绕过未确认动作。

验证涵盖重复提交、持久恢复、文件锁、模拟只读写入失败、崩溃未完成意图、坏尾部、数量/身份不匹配、取消和刷新失败；测试不发送游戏输入。
