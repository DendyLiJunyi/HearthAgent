# 决策执行时间窗口

控制器现在要求显式 `ExecutionWindow`，在模型推理开始前创建，绑定当时的完整 `Snapshot`，在重新观察后原样传入 `Controller::execute`。

```rust
let window = ExecutionWindow::new(&observation.snapshot, budget)?;
let decision = policy.decide(&observation)?;
let current = source.observe()?;
let outcome = controller.execute(&current, &decision, &window, &mut executor)?;
```

以上为调用顺序示意，错误类型需由调用方转换。`budget` 由未来调度器根据剩余回合时间与操作余量决定；当前离线 demo 使用十秒示例预算，不代表真实回合时间。

## 行为

- 使用进程内单调时钟 `Instant`，不依赖系统时间调整；达到截止点即拒绝，零预算或截止时间溢出拒绝创建。
- 窗口绑定会话、版本、阶段和完整度。即使决策与新观察彼此匹配，也不能拿另一快照的窗口执行。
- `window.clone()` 保留同一截止点并共享取消标志。其他线程可调用 `cancel()`；该窗口无法恢复，不能修改截止时间。
- 执行入口和去重记账前各检查一次，返回 `DeadlineExpired`、`Cancelled` 或 `StaleDecision`。未调用执行器的拒绝不消耗尝试次数。
- 真正调用执行器之前仍先记录尝试，执行器报错或结果不明后，不能通过新建窗口绕过去重保护。

调度器不得在收到过期结果后新建窗口来延长旧决策；需要重新观察和重新决策。接口无法证明调用方在何时创建窗口或是否真正重新采样，这仍是适配器职责。

## 边界

这是提交前检查，不是中断正在执行的动作，也不保证执行在截止点之前完成。取消标志在最后检查之后改变时，无法撤销已经进入的执行器调用。未来多阶段输入执行器仍需在每次输入前检查停止状态、剩余时间和实际 UI；目前没有实现这类游戏输入执行器。

窗口取消不终止 Laya HTTP 请求或 GPU 推理；现有 HTTP 超时继续独立工作。窗口不可持久化或跨进程传递。日志完整性、候选合法性和决策质量要求保持不变。

后续已添加 [StepRunner 和可选持久账本](control-runner.md)。runner 共享运行级停止信号，并从首次采集前开始计时。持久意图同步后再次检查截止时间；若此时过期/取消，记录 NotDispatched 并保留尝试键，此类拒绝不能通过重试同一状态重新发送。

## 验证

新增测试覆盖精确截止边界、无效预算、跨线程取消、取消拒绝不记账、同局面过期拒绝、跨会话窗口拒绝，以及 HTTP 成功返回但已超过执行预算的模型回复。88 项全套 Rust 测试通过，随后新增的延迟模型回归及全部九项 Laya 测试通过（当前共 89 项）；Clippy 无警告，离线 demo 的重复执行仍被拒绝。
